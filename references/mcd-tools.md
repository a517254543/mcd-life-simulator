# MCP 工具速查与数据边界（本项目）

实测环境：`https://mcp.mcd.cn`，测试门店 `1450713`（上海黄浦华旭国际大厦餐厅），
数据基准日 2026-10-13。

## 一、本项目用到的 5 个工具

| 工具 | 用途 | 报告段落 |
|---|---|---|
| `query-nearby-stores` | 定位门店拿 `storeCode` | 第 2 步 |
| `query-meals` | 拉该店真实在售菜单与价格 | 第 5 段「专属套餐」 |
| `available-coupons` | 当前可领优惠券 | 第 6 段「小吉」 |
| `campaign-calendar` | 当月营销活动日历 | 第 6 段「上上签」 |
| `list-nutrition-foods` | 能量/蛋白/脂肪/碳水/钠/钙 | 第 3 段「脂肪」折算依据 |

另有 `query-meal-detail` / `calculate-price`：仅当用户对推荐餐品
提出特调需求时才调用（见 SKILL.md「特调传参规则」）。

## 二、调用方式

```
query-nearby-stores(searchType=2, beType=1, city=<城市>, keyword=<关键词>)
query-meals(storeCode=<code>, orderType=1, beType=1)
available-coupons()                       # 无参数
campaign-calendar()                       # 无参数，默认返回当月全部
list-nutrition-foods()                    # 无参数
```

`campaign-calendar` 可传 `specifiedDate`（`yyyy-MM-dd`）锚定某天前后各一天，
不传则返回当前月全部活动。本项目用不传参数的默认行为。

## 三、字段陷阱（实测）

### 1. `query-meals` 的价格是字符串形式的元

`currentPrice` 形如 `"25.5"`（不是数字、不是分）。
报告里展示时直接用，不要乘除 100。

`originalPrice` 是划线价，可用于「立省 X 元」类表述。
`discountType` 标注优惠类型（`null` / `早餐卡优惠` / `促销优惠` /
`麦金卡优惠` / `随单购麦金卡优惠`）。

### 2. `query-meals` 的分类名里带换行

分类名形如 `"鸡肉汉堡\n/卷"`、`"小食拼盘\n/多人餐"`、`"安格斯MAX\n厚牛堡"`。
**引用分类名时把 `\n` 替换为空格或斜杠连接**，不要原样带进报告。

### 3. 菜单 code 有两套体系

短数字码（`1100` 巨无霸、`1120` 双层吉士汉堡、`1440` 麦辣鸡腿汉堡、
`1450` 麦香鸡、`521953` 龙焰芝士棒鸡腿堡、`4810` 薯条、`515837` 圆筒冰淇淋）
与长码（`9900016073` 龙焰鸡腿堡三件套等 990 开头套餐）。
两套都在 `data.meals` 映射表里，按返回原样引用，不要自己拼 code。

### 4. 单品与套餐的顶层结构不同

- 单品：`data.meals.{code}` 直接就是餐品详情。
- 套餐：同样在 `data.meals` 里，但 `tags` 常含 `套餐`，
  `withOrder` 字段标注随单购卡（`membershipCode` / `specId`）。
  带 `withOrder` 的套餐价格依赖麦金卡，报告中提价格时可注明
  「麦金卡价」，不要当成普适价。

### 5. `available-coupons` 的图片是带签名的临时 URL

券图片地址含 `q-sign-time` 签名参数，**会过期**。
报告只引用券名称与状态，不引用图片 URL。

### 6. `campaign-calendar` 混合了三种时间状态

返回按日期分节：`往期回顾` / `今日` / 未来日期。
**只取今日及未来的活动。** 往期活动写进「本月运势」属于事实错误。

活动文案本身带大量 emoji 与营销语气（如「速戳👇快定好闹钟」），
引用时改写成报告的语体，保留事实（时间、价格、机制），
去掉吆喝语气。

### 7. `list-nutrition-foods` 的字段与杂质

返回字段仅有：

```
productName, nutritionDescription, energyKj, energyKcal,
protein, fat, carbohydrate, sodium, calcium
```

- `nutritionDescription` 绝大多数为 `null`，少数是类比描述
  （如「能量约清水1杯」），可作趣味素材但不精确。
- 存在内部测试名称（`yeyeyeye奶冻款`、`yeyeyeye爆珠款`）与重复项
  （`小杯玉米杯`、`纯牛奶（盒装）`各出现两次）。按名称去重，异常名称跳过。

### 8. 菜名含「芝士」不等于配料表含吉士（本项目的招牌反例）

实测 `521953 龙焰芝士棒鸡腿堡`（¥27）名称含「芝士」，
但 `query-meal-detail` 返回的配料仅为 **辣椒黄油风味酱、切块生菜**，无吉士项。

报告中「注意」一行的素材来自这里：**名实不符是真实存在的，
但必须用 `query-meal-detail` 验证后才写**。不验证就当没这条素材。

### 9. `query-meals` 返回的 code 不保证能取到详情

实测 `1406 板烧鸡腿堡` 在 `query-meals` 的「鸡肉汉堡/卷」分类中在售
（¥23.5），但 `query-meal-detail` 返回 `60001 未匹配到商品`。

本项目的套餐推荐**不依赖** `query-meal-detail`，正常流程不受影响；
仅当用户要求特调验证时才可能撞上，撞上就如实说明。

### 10. `calculate-price` 的 items 数组在部分客户端下解析失败

实测在 WorkBuddy 当前工具调用层，`calculate-price` 的 `items` 数组参数
报 `/items: must be array`，最简合法入参同样失败。判断为客户端
数组参数序列化问题，非接口 schema 变化。

本项目核心流程（出报告）不经过算价接口；仅「用户要求算特调价」时
可能用到。失败时如实告知，给 `query-meals` 原价作参考，
**不伪造算价结果**。
