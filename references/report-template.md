# 报告模板与文案规则

写《麦门人生报告》前必读本文件。

## 一、报告结构（六段，顺序固定）

| 段 | 标题 | 内容 | 数据来源 |
|---|---|---|---|
| 1 | 报告头 | 报告编号、门店、数据日期 | 第 2/3 步 |
| 2 | 2027 年人生轨迹 | 3-4 句幽默叙事 | 无（纯创作） |
| 3 | 隐藏属性 | 4 个属性，各带一句依据 | 属性规则见下 |
| 4 | 人生关键词 | 一句话，加引号 | 无（纯创作） |
| 5 | 你的专属套餐 | 工作日 + 加班夜两行 | `query-meals` 真实餐品 |
| 6 | 本月麦门运势 | 上上签 / 小吉 / 注意 三行 | `available-coupons` + `campaign-calendar` |

固定收尾三行（免责与数据基准）见 SKILL.md 第 7 步，不可省略。

## 二、报告头

```
《你的麦门人生报告》
报告编号 MCD-2027-<MMDD> · 门店 <storeCode> · 数据日期 <yyyy-MM-dd>
```

## 三、人生轨迹（第 2 段）文案规则

写 3-4 句，句式参考：

```
你成为了一名<职业的下一级>。
因为<与麦当劳相关的具体习惯>，
你的<某个可量化的日常指标><变化>。
<时间点>，你会因为<某个麦当劳场景>陷入短暂的人生思考。
```

允许的幽默素材：
- 与职业相关的自嘲（程序员与生产环境、产品经理 battle；设计师与改稿）
- 麦当劳场景的荒诞化（第二份半价、积分过期前夜、周末早餐卡）
- 社交平台梗（MBTI、水群、摸鱼）

禁止的幽默素材：
- 收入、外貌、身材、年龄焦虑
- 感情状态的负面调侃（「单身所以吃堡」这类不行）
- 任何可能让用户觉得被嘲笑个人处境的表达

判断标准：这句笑话换成用户的同事看，用户会愿意截图吗？
不愿意就重写。

## 四、隐藏属性（第 3 段）数值规则

四个固定属性位：**效率 / 快乐 / 脂肪 / 钱包**。

| 属性 | 允许的取值范围 | 依据要求 |
|---|---|---|
| 效率 | +5 ~ +20 | 必须关联一个真实优惠（如「9.9 元早餐两件套省掉决策」） |
| 快乐 | +10 ~ +30 | 必须关联本月真实活动或上新 |
| 脂肪 | +3 ~ +12 | 必须给出 kcal 折算过程，见下 |
| 钱包 | -10 ~ +10 | 必须关联真实省钱机制（麦金卡、优惠券、随心配） |

### 脂肪属性的折算规则

用 `list-nutrition-foods` 的真实数值：

```
每次约 <单次餐品 energyKcal 合计> kcal
每周 <用户频率> 次
一年约 <kcal × 52> kcal
```

报告里只展示最终数值与一句依据，不展示完整算式。
数值取 `+N` 的形式，N 按 `年kcal ÷ 7700`（约 7700 kcal ≈ 1kg 脂肪）折算后取整。

若用户频率 ≤ 1 次/周，脂肪给 +3 ~ +5 并在依据里注明「频率友好」。
**任何情况下不使用恐吓性表述**（如「你会胖 X 斤」），这是娱乐推算。

### 收入的处理

用户给了月收入：只决定第 5 段套餐的价位带，不在任何段落评价收入本身。

| 月收入 | 套餐价位带（单次） |
|---|---|
| 未提供 | ¥15 ~ ¥40 |
| < 5000 | ¥13 ~ ¥25（随心配、经典单品） |
| 5000 ~ 15000 | ¥17 ~ ¥45 |
| > 15000 | ¥25 ~ ¥95（四件套、联名周边） |

价位带只用于从真实菜单里选品，不写进报告。

## 五、人生关键词（第 4 段）

一句话，加书名号或引号。要求：

- 与职业或人生状态弱相关即可，不要求强逻辑
- 可以化用名言、歌词、网络梗，但**不出现其他品牌名**
- 一句就好，不写多句

示例（程序员）：「代码改变世界，麦当劳填满胃。」

## 六、你的专属套餐（第 5 段）搭配规则

固定两行：**工作日** 与 **加班夜**。

选品规则：

1. 只能从 `query-meals` 当前返回里选。**套餐类也可以整体推荐**
   （如「龙焰鸡腿堡三件套 ¥26.9」），此时直接引用其 `currentPrice`。
2. 工作日推荐早餐或轻食组合（用户频率 ≥ 3 次/周时优先早餐场景，
   因为该频率暗示通勤规律）；
   频率 < 3 次/周时推荐正餐组合。
3. 加班夜推荐高热量组合（牛堡、芝士、炸鸡），呼应「深夜食堂」场景。
4. 单行价格格式：`餐品名 ¥价格`，组合用 ` + ` 连接，价格各自标注。
5. 每行下面可跟一句斜体依据（营养数据或优惠机制），非必填。

示例：

```
工作日 · 麦香鸡 ¥17 + 浓缩咖啡 ¥15
  蛋白质 15g、钠 731mg，资深程序员的基础操作
加班夜 · 双层吉士汉堡 ¥23
  牛肉加吉士，凌晨的编译器需要这个
```

## 七、本月麦门运势（第 6 段）数据规则

固定三行：**上上签 / 小吉 / 注意**。

| 行 | 内容要求 | 来源 |
|---|---|---|
| 上上签 | 本月最值得关注的一个活动或周边 | `campaign-calendar` 进行中活动 |
| 小吉 | 1-2 张当前可领的优惠券 | `available-coupons` 状态为可领取 |
| 注意 | 一条「有趣的真实反差」 | 优先用菜单里的名实不符项 |

「注意」这一行的素材优先级：

1. 菜名与配料表不一致的项（如「龙焰芝士棒鸡腿堡」名字含芝士、
   实测配料表无吉士——需用 `query-meal-detail` 验证后才可写）
2. 名称易误读的项（如「北美招牌牧场酱」是蘸酱、「灰焰圆筒」是冰淇淋）
3. 当月经销活动的时间陷阱（如「10 月 21 日截止」）

**没有验证过的反差不写。** 这一行的趣味必须建立在真实数据上，
宁可少一条，不可编一条。

## 八、收尾三行（固定）

```
以上餐品、价格、优惠与活动均来自麦当劳 MCP 实时数据（门店 <编号>，<日期>）。
「脂肪」等属性为娱乐性推算，不构成营养或医学建议。
餐品供应与价格以门店实际为准。
```
